Toen ik mijn portfoliosite voor het eerst bouwde, wilde ik snelheid, eenvoud en een moderne tech stack. Daarom koos ik voor Astro. Het voelde snel, overzichtelijk en licht. Een tijdlang werkte het perfect.

Maar naarmate mijn ambities voor de site groeiden, liep ik tegen grenzen aan. Ik wilde niet langer alleen statische pagina’s. Ik wilde dynamische functies, slimmere routing en een codebase die ik zonder kopzorgen kon laten groeien. Op dat moment besefte ik dat Astro niet meer bij me paste.

Dus stapte ik over op Angular. En daar heb ik geen seconde spijt van.

Waarom Astro in het begin geweldig was

Astro is eerlijk gezegd fantastisch voor eenvoudige sites. Statische generatie is razendsnel. Ik vond het geweldig dat ik React of andere componenten kon toevoegen zonder bergen JavaScript mee te sturen. Mijn blog en een paar statische pagina’s laadden bijna direct, en meer had ik in het begin niet nodig.

Maar zodra ik iets geavanceerders wilde, werd het rommelig. Ik begon JavaScript aan elkaar te plakken voor interactiviteit. Routing voelde beperkt. Voor state management had ik extra libraries nodig. De eenvoud die Astro zo goed maakte, werd ook mijn knelpunt.

Waarom ik overstapte op Angular: 4 grote winsten voor mijn situatie

1. Gedeelde state en services die gewoon werken

Astro bood me geen nette manier om state te delen tussen verschillende delen van de site. Ik moest jongleren met context providers en globale stores, en het voelde alsof alles met ducttape aan elkaar hing.

Angular gaf me dependency injection en services standaard mee. Ik kan bedrijfslogica gescheiden houden van componenten en overal data delen zonder het wiel opnieuw uit te vinden.

2. Echte kracht in routing

Astro handelt statische routing prachtig af, maar schiet tekort zodra je dynamische routing met parameters, guards of lazy loading wilt.

De router van Angular speelt in een andere klasse. Ik kan routes met parameters bouwen, ze beschermen met guards en modules lazy laden om de app snel te houden. Het is alsof je van lokale straatjes overstapt op een volledig snelwegennet.

3. Echt overal TypeScript

Astro ondersteunt TypeScript, maar het is niet zo afgedwongen of diep geïntegreerd als in Angular. Angular leeft en ademt TypeScript. Templates, services, routing: alles profiteert van sterke typering.

Het heeft me bij refactoring voor talloze bugs behoed. Ik weet precies wat waar verwacht wordt, en dat houdt mijn code veiliger en beter onderhoudbaar.

4. CLI en tooling die het leven makkelijker maken

De eenvoud van Astro is mooi, maar als je project groeit, moet je veel tools zelf aan elkaar knopen.

De CLI van Angular geeft me commando’s om componenten, services en modules te genereren, plus geautomatiseerde tests en productiebuilds. Dat scheelt enorm veel tijd en helpt me mijn code georganiseerd te houden.

Hoe mijn site is veranderd

Sinds de overstap naar Angular is mijn portfolio niet langer alleen een statische site. Het is een kleine app.

  • Ik heb dynamische weergave van content toegevoegd
  • Blogartikelen laden dynamisch via routeparameters
  • Ik ben voorbereid op toekomstige integraties, zoals API’s of authenticatie
  • De codebase is gestructureerd en makkelijker te onderhouden

Astro was perfect toen ik alleen een lichte statische site wilde. Maar mijn visie ontgroeide wat het comfortabel aankon.

Zou ik Angular iedereen aanraden?

Niet per se. Als je een eenvoudige blog of marketingpagina bouwt, is Astro briljant. Het is snel, modern en minimalistisch.

Maar als je vooruitdenkt aan dynamische functies, complexe routing of onderhoudbaarheid op grote schaal, kan Angular je later veel kopzorgen besparen.

Tot slot

Het is makkelijk om verliefd te worden op nieuwe frameworks. Astro was geweldig toen mijn wensen nog klein waren. Maar je technische keuzes moeten je doelen volgen, niet andersom.

Ik ben blij dat ik de overstap heb gemaakt. Mijn site is krachtiger en toekomstbestendiger, en ik heb er vertrouwen in dat ik er nog jaren op kan voortbouwen.
